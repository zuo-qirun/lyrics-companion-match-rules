# 规则格式

一个规则包（rule pack）就是一份 JSON，schemaVersion 固定为 1。

~~~json
{
  "schemaVersion": 1,
  "id": "vendor.split-artist-title",
  "name": "厂商：拆分歌手与歌名",
  "version": 1,
  "author": "author-name",
  "description": "说明这条规则解决什么问题",
  "minVersionCode": 0,
  "scope": {"packages": ["com.example.player"], "sources": []},
  "rules": []
}
~~~

## 字段约束

| 字段 | 约束 |
| --- | --- |
| schemaVersion | 必须为 1 |
| id | 3–64 字符，小写字母/数字开头，可含 . _ - |
| name | 1–40 字符 |
| version | 1–9999 整数；同 id 新版本必须递增 |
| author | 0–40 字符 |
| description | 0–200 字符 |
| minVersionCode | 0–999999；应用版本低于它时忽略该包 |
| scope.packages | 最多 20 个包名；空数组表示不限 |
| scope.sources | 最多 8 个：netease/qqmusic/kugou/kuwo/soda/migu |
| rules | 1–64 条 |

## 作用域

- 有 packages 的规则包只会对匹配的播放器生效；提交市场时优先使用这种方式。
- 没有 packages 的全局包会影响所有播放器，审核更严格，安装时应用会二次确认。
- sources 用于只在某个词库候选上生效的高级场景，一般留空。

## 版本

- 新包从 version 1 开始。
- 修改已上架包：保持 id 不变、version +1 重新提交；审核通过后替换旧版本。
- 需要彻底替换语义时换新 id，并在说明里写清与旧包的关系。

## 安全限制

整包序列化不超过 32KB；正则不超过 200 字符；单包正则合计不超过 64 个；禁止命名捕获组、反向引用、嵌套量词。
